Al principio no entendía para qué necesitaba Redis si ya tenía PostgreSQL, pero me di cuenta de que se complementan. PostgreSQL guarda los datos importantes como usuarios, libros, pedidos y pagos, y Redis se queda con lo temporal que necesita ser muy rápido. Como mis seis microservicios están separados, Redis funciona como el punto en común donde todos comparten las sesiones, los refresh tokens y la lista de tokens revocados usando la misma URL protegida con contraseña. Así, cuando alguien hace logout, su token deja de servir en todos los servicios al instante y no hasta que se vence a los veinte minutos.

Sobre los endpoints, aprendí que las consultas públicas como ver los libros o los autores pueden quedarse abiertas y usar Redis como caché por sesenta segundos para no ir a la base de datos cada vez. En cambio, todos los POST, PUT, PATCH y DELETE y las lecturas de usuario o administrativas como mis pedidos, mis pagos o la lista de usuarios deben pedir JWT y revisar el role_id, regresando 401 si el token no sirve y 403 si no tiene permiso. Para implementarlo hice un módulo común para que todos validen el token igual, y decidí que si Redis se cae el caché siga funcionando desde PostgreSQL, pero las sesiones y la revocación fallen de forma segura, porque prefiero rechazar un token que dejar pasar a alguien que ya cerró sesión.

También lo usé en pedidos y pagos para cosas temporales, como apartar el stock de un pedido por quince minutos, evitar con un candado que un pedido se pague dos veces al mismo tiempo y guardar una llave para que no se cobre doble si el usuario le da dos veces a pagar. Por último, la app de Tkinter renueva el token a los diecisiete minutos para que no caduque mientras se usa, y la llave secreta que firma los tokens la comparten todos los servicios desde variables de entorno y nunca está escrita en el código.
